## 2026-09-23 — Единое меню бэк-офиса: один каркас на админке, складе и в CRM менеджера

- Меню «Меню» + выдвижная панель разделов (изначально сделанное на складе) распространено на все поверхности бэк-офиса: `AdminLayout` лишился постоянного сайдбара (кнопка «Меню» в шапке), для `/manager/*` создан `ManagerLayout` с тем же каркасом (шапка ГУСТО/пользователь/«Выйти» переиспользует стили AdminLayout).
- Источник пунктов — один: `components/admin/adminNav.ts` → `backofficeNavItems(role)`; новые разделы добавлять только туда. Набор по роли: ADMIN — Дашборд, Документы, Склад, Единое окно, Заказы, CRM, Обмен 1С + CRUD/оперцентр; ACCOUNTANT — Дашборд, Документы, Склад, Обмен 1С; MANAGER — Единое окно, Заказы, Воронка, Клиенты, CRM, Документы, Склад.
- Общий компонент — `components/admin/BackofficeMenu.tsx` (кнопка `aria-expanded`/`aria-controls` + панель); стили панели в `BackofficeMenu.module.scss` (вид бывшего сайдбара; ≤720px — во всю ширину).
- Дублирующие строковые навигации со страниц менеджера (Заказы, Единое окно) удалены — разделы теперь только в общем меню; контекстные ссылки внутри сценария («К списку заказов») сохранены.
- Мотивация: у владельца меню выглядело по-разному на админке, складе и в CRM; просьба — «сделать одинаковым на всех страницах».

## 2026-09-23 — Склад: разворачиваемая панель бэк-офиса («Меню»), единый список пунктов админки

- `WarehouseLayout` получает панель бэк-офиса, скрытую по умолчанию: кнопка «Меню» в шапке склада (`aria-expanded`/`aria-controls`, открытое состояние — бордо) разворачивает левую панель со стилями сайдбара админки; на экранах ≤720px панель становится полноширинным блоком над контентом.
- Пункты панели: для ADMIN/ACCOUNTANT — те же, что в сайдбаре админки; для MANAGER — разделы менеджера (Единое окно, Заказы, Воронка лидов, Клиенты, CRM), у менеджера своего сайдбара нет. Мотивация: «Склад» из сайдбара админки вёл на отдельный layout без обратной навигации — путь назад был только через кнопку браузера.
- Список пунктов админки вынесен в `components/admin/adminNav.ts` (`adminNavItems` по матрице 2.1) — единый источник для `AdminLayout` и панели склада; пункты по ролям не разъезжаются. Новые разделы админки добавлять только туда.

## 2026-09-23 — Ссылка-кнопка — только LinkButton; вложенные интерактивные элементы запрещены; модалки — только UI Modal

- Навигация, выглядящая как кнопка, — компонент `LinkButton` (`react-router` `<Link>` с классами `Button.module.scss`): один tab-стоп, валидный HTML, единый вид с Button — plan-07. Оборачивать `<Button>` в `<Link>` (и любые вложенные интерактивы) запрещено.
- Переключатели-состояния (бейджи «ХИТ»/«НОВИНКА» в админке) — `<button>` с `aria-pressed`, `title` и hover/focus-visible-каймой; бейдж внутри — только визуал.
- Модальные окна — только UI `Modal` (Escape, клик по фону, aria-modal из компоненты); кастомные overlay-дивы запрещены, существующие переведены (детали заказа кабинета, карточка клиента CRM, CMS-редактор) — plan-07.
- Кнопки удаления строк (позиции складских документов/заказов поставщикам) имеют `aria-label="Удалить позицию"`; строка позиций — flex с ролями колонок, не вылезает за модалку на 1440px и 390px.

## 2026-09-23 — Все мутирующие кнопки обязаны блокироваться на время запроса (Button loading); await без try/catch+toast запрещён

- Кнопка, запускающая сетевую мутацию, обязана на время запроса переходить в `loading` (компонент `Button`: disabled + спиннер) — двойной клик не может отправить запрос дважды — plan-03. Паттерн един: busy-стейт / `mutation.isPending` + `loading={busy}`; «disabled»-костыли через CSS запрещены. Для react-query-мутаций на строках таблиц: `loading={mutation.isPending && mutation.variables === row.id}`; для PDF-кнопок — один `pdfBusyId` на страницу (параллельные скачивания не запускаются).
- Каждый `await` мутации обёрнут в try/catch с `push(message, "error")` — unhandled rejection невозможен (до фикса: «Очистить корзину», массовое добавление по артикулам).
- Ревью-критерий: для каждой кнопки с сетевым вызовом — либо loading, либо вызов не сетевой (локальный `cartStore.addItem` витрины синхронный — блокировка не требуется).

## 2026-09-22 — Бэк-офис на бренд-токенах; новые hex-цвета в scss запрещены; формат денег единый

- Хром бэк-офиса (админка, менеджер, кабинет, склад, документы) — только на токенах `_tokens.scss`: вторичный текст `rgba($color-graphite, …)`, границы `$color-line`, подложки `$color-card`/`$color-cream`, акцент `$color-bordeaux` — plan-05. CSS-переменные с hex-fallback'ами (`#6b7280`, `#8c1d1d`, `#e5e5e0`, …) удалены — переменные нигде не определялись, рендерились fallback'и.
- Новые hex-цвета в `.scss` вне `_tokens.scss` запрещены (проверка: grep по hex → 0); размеры/отступы/сетки не менялись.
- Нестилизованные ссылки навигации бэк-офиса — класс `.pageLink` (общий, в `index.scss`: Oswald uppercase, бордо на сливках, hover темнее); нативные `select`/`input` — только через UI-компоненты; чекбоксы — `accent-color: $color-bordeaux` в label.
- Формат денег единый — `formatMoney` с суффиксом « р.» (рекомендация бренд-бука; гейт «Br vs р.» решён по умолчанию в пользу бренд-бука): витрина и бэк-офис показывают цену одинаково, единицы «р./кг», «р./уп». Точность (2 знака, запятая) сохранена.
- «В корзину» на витрине — вариант accent (жёлтый, по бренд-буку и UiKit), не secondary/primary.

## 2026-09-22 — Деструктивные действия — только через ConfirmModal, window.confirm запрещён

- Единый `ConfirmModal` (поверх `Modal`) для всех необратимых/деструктивных действий: провести/отменить складской документ, отправить/отменить заказ поставщику, выпустить счёт, лид «Потерян», удаление фото/пользователя/компании, публикация/архив CMS, применение импорта 1С, очистка корзины, смена пароля, отмена заказа менеджером — plan-02.
- Нативные `window.confirm` удалены (AdminUsers/AdminCompanies); новых не добавлять.
- Клавиатура: Enter — подтвердить, Escape/✕/клик по фону — отмена; при открытии фокус на «Отмене» (защитный дефолт); на время запроса `loading` блокирует оба действия.
- Опасность передаётся формулировкой, не цветом: кнопка подтверждения остаётся primary (бордо), красный цвет вне бренд-палитры.
- «Создать и отправить» в заказе поставщику разделён: «Создать черновик» + отдельное подтверждаемое «Отправить».

## 2026-09-22 — Поле количества в корзине: коммит по blur/Enter

- Поле количества коммитится по blur/Enter (или debounce); пустое значение не отправляется; удаление позиции — только кнопкой «Убрать» (plan-04).
