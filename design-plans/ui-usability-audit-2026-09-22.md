# UI/UX-аудит «Густо» B2B-портала — витрина и бэк-офис

> Дата: 2026-09-22 · Метод: код-ревью всех 54 tsx-файлов + рендер-проход в браузере
> (1440×900 + мобильный 390×844, деплой локальный: backend :8080 + vite :5173,
> миграции+сиды V1–V24). Проверены роли: гость, CUSTOMER_INDIVIDUAL, MANAGER
> (+склад/документы), ADMIN (все разделы, сброс пароля), CUSTOMER_LEGAL (документы).
> Создан тестовый заказ З-2026-00001, счёт-негатив на заказе физлица.
> Статус: черновик для приоритизации; планы правок пишутся только по выбранным пунктам.

## Design language

- Audited surface: всё веб-приложение (витрина `/`, `/catalog`, `/products/*`, статические;
  auth; кабинет клиента `/cabinet/*`; менеджер `/manager/*`; склад `/warehouse/*`;
  документы; админка `/admin/*`; `/ui-kit`).
- Design sources: `docs/brandbook/` (6 стр.), `frontend/src/styles/_tokens.scss`,
  `docs/decisions.md` (токены из бренд-бука, Часть 1.7), `pages/UiKitPage.tsx` (приёмка S06).
- Documented decisions: палитра бордо `#7C2D24` (знак, кнопки, шапка), сливки `#F5EDDE` (фон),
  желток `#E5A33C` (акцент: «в корзину», ценники, акции), графит `#26201C` (текст);
  шрифты Russo One (H1/цены), Oswald (H2/кнопки/меню, прописные, разрядка 4–8 px),
  Rubik (текст, 1.5–1.6); пропорция 60/25/10/5; запреты: бордо на графите, желток фоном
  больших блоков, новые цвета (синий/зелёный/фиолетовый), тени/градиенты.
- Governing owners and consumers: `Button` (3 варианта), `Badge` (5), `Input/Select/Textarea`,
  `Modal` (Escape+aria), `Tabs`, `Pagination`, `Toast`, карточка `Card`; потребители — все страницы.
- Explicit exceptions: None documented (семантические статусы «успех/внимание» сведены
  к бордо/желтку — осознанное следование палитре, задокументировано только в коде Badge).

## Что хорошо (сохранить)

- Витрина целиком в бренд-палитре и типографике: шапка бордо, Russo One в H1/ценах,
  фирменный ценник на плитке товара, marquee-лента категорий.
- Пустые состояния почти везде с подсказкой-действием («Счетов пока нет — выставите
  счёт из заказа», «Пул пуст — все заказы разобраны»).
- Контекстные ограничения на уровне UI: `Применить`/`Сохранить`/`Создать счёт` disabled
  до валидных данных; статусы в селекте менеджера фильтруются по текущему статусу заказа.
- Идемпотентность создания заказа (`crypto.randomUUID()`), ошибки бэкенда —
  человекочитаемые русские тексты (ErrorCode).
- Auth-формы: block-кнопки с loading, ссылки «Забыли пароль?»/«Регистрация» на месте.

## По-кнопочный аудит

Формат: `кнопка — состояние`. ✅ = замечаний нет; ⚠️ = замечание; ❌ = проблема.
Отмечены только отклонения; полное соответствие паттерну не дублируется.

## Improve first

**S1 (единый layout кабинета) + S2 (ConfirmModal для деструктивных) — максимальный рычаг.**
S1 — самая частая жалоба реального пользователя (навигация пропадает при каждом переходе)
и чинится одним layout-компонентом на все `/cabinet/*` + переносом системных ссылок в
бренд-стиль. S2 закрывает 12+ рисков необратимых действий одним переиспользуемым
компонентом (`Modal` уже умеет всё нужное — в UiKit паттерн показан, осталось применить).
